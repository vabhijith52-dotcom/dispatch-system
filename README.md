# AI-BASED TRUCK LOADING MONITORING AND CARTON COUNTING SYSTEM

## Project Overview

The **AI-Based Truck Loading Monitoring and Carton Counting System** is a computer-vision-based solution developed to monitor truck/container loading operations. The system converts loading-bay video into structured operational information by detecting trucks, cartons, number plates, open loading doors and containers.

The system uses a custom-trained **YOLO object-detection model** for object detection. Detected cartons are tracked across video frames using **ByteTrack**. A centroid-based door-entry rule with temporal validation, also referred to as debouncing, is used to determine whether a carton has actually entered the loading region. This helps reduce incorrect carton counts caused by temporary detection fluctuations.

The system also includes **PaddleOCR** for number-plate recognition, **FastAPI** for backend services, **PostgreSQL** for data storage and a **React-based dashboard** for monitoring loading operations in real time.

---

## Key Features

### 1. AI-Based Object Detection

The custom YOLO model detects the following objects:

* Truck
* Number Plate
* Carton Box
* Open Door
* Container

The detected objects form the perception layer of the system.

### 2. Carton Tracking

**ByteTrack** is used to maintain the identity of cartons across consecutive video frames.

Tracking prevents the same carton from being treated as a new object every time it is detected in a different frame.

### 3. Carton Counting

The system does not simply increment the count whenever a carton is detected.

The counting workflow is:

Carton Detection
↓
Track ID Assignment
↓
Centroid Calculation
↓
Door Region Check
↓
Temporal Validation / Debouncing
↓
Valid Door Entry
↓
Carton Count +1

This approach helps reduce duplicate counts and false increments caused by temporary detection fluctuations.

### 4. Number Plate OCR

The detected number-plate region is processed using **PaddleOCR**.

The OCR pipeline consists of:

Number Plate Detection
↓
Plate Crop
↓
Image Preprocessing
↓
PaddleOCR
↓
Recognized Plate Text
↓
Truck Record

The recognized number plate is associated with the corresponding truck record.

### 5. FastAPI Backend

FastAPI is used to provide backend services for:

* User authentication
* Truck records
* Loading events
* Carton counts
* Dashboard information
* API communication
* Real-time updates

### 6. PostgreSQL Database

PostgreSQL stores the operational information generated by the system.

The database contains information related to:

* Users
* Trucks
* Expected carton count
* Loaded carton count
* Loading status
* Loading start time
* Carton-count events
* Track IDs
* Event timestamps

### 7. Real-Time Dashboard

The React dashboard provides:

* Current truck information
* Number plate
* Expected cartons
* Loaded cartons
* Remaining cartons
* Loading status
* Live detection information
* Loading activity
* Daily loading summary
* Recent loading sessions
* Date filtering
* Manual expected-carton editing
* Excel export

# Dataset Preparation

The source video was converted into representative frames for dataset preparation.

The selected frames were annotated using **CVAT**. Bounding boxes were created for the required object classes and the annotations were exported in a YOLO-compatible format.

The dataset was then prepared for training and evaluation of the custom YOLO model.

# Model Evaluation

The final model evaluation produced the following results:

| Metric        | Result |
| ------------- | -----: |
| Precision     | 91.60% |
| Recall        | 99.38% |
| mAP@0.50      | 97.18% |
| mAP@0.50:0.95 | 79.27% |

### Class-Wise Results

| Class        | Precision | Recall | mAP@0.50 | mAP@0.50:0.95 |
| ------------ | --------: | -----: | -------: | ------------: |
| Truck        |     94.0% |   100% |    97.3% |         77.0% |
| Number Plate |     90.4% |   100% |    95.2% |         56.8% |
| Carton Box   |     87.7% |  96.9% |    98.5% |         87.0% |
| Open Door    |     92.1% |   100% |    97.1% |         86.8% |
| Container    |     93.8% |   100% |    97.8% |         88.8% |

The evaluation was performed on **52 images containing 347 object instances**.

The detection metrics represent the performance of the object-detection model. They should not be interpreted directly as the accuracy of the final carton-counting system because the counting stage additionally uses tracking, spatial validation and temporal validation.

# Carton Loading Logic

Simple object detection cannot be directly used for carton counting because the same carton appears in multiple consecutive video frames.

For this reason, the system combines object detection, tracking and spatial-temporal validation.

The counting logic is:

1. Detect the carton using YOLO.
2. Assign and maintain a track using ByteTrack.
3. Calculate the carton centroid.
4. Monitor the centroid relative to the loading-door region.
5. Apply temporal validation/debouncing.
6. Confirm a valid door-entry event.
7. Increment the carton count.
8. Store the event in PostgreSQL.
9. Update the dashboard.

A carton detection therefore does not automatically result in a carton count.

# Loading Status Logic

The system maintains different loading states.

WAITING
↓
First valid carton event
↓
LOADING
↓
Loaded count reaches expected count
↓
COMPLETED

The expected carton quantity can also be manually updated from the dashboard, after which the remaining quantity and loading progress can be recalculated.

# Number Plate Recognition

The number plate is first detected using the YOLO model.

The detected region is cropped and processed before being passed to PaddleOCR.

The workflow is:

Number Plate Detection
↓
Crop Plate Region
↓
Resize / Preprocess
↓
PaddleOCR
↓
Plate Text
↓
Truck Record

This allows the system to associate vehicle identification information with the corresponding truck-loading session.

# Project Limitations

The system was developed and evaluated using the available loading-bay video data. Performance may vary under different operational conditions such as:

* Camera movement
* Lighting variations
* Object occlusion
* Background objects
* Different carton appearances
* Different camera angles
* Poor video quality
* Number-plate visibility

The system should therefore be further validated using larger and more diverse datasets and live operational camera feeds before production deployment.
